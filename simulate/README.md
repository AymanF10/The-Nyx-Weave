# Nyx Weave Devnet Simulation Scripts

This directory contains comprehensive simulation scripts for testing the Nyx Weave arbitrage platform on Solana devnet. The scripts are designed to work together and maintain state between runs.

## 📁 Files Overview

- `0_setup_devnet.ts` - Initial setup and program initialization
- `1_create_strategy.ts` - Create strategy vaults for different risk levels
- `2_deposit.ts` - User deposit simulation
- `3_withdraw.ts` - User withdrawal simulation
- `4_execute_arbitrage.ts` - Arbitrage execution simulation
- `5_claim_profits.ts` - Profit claiming simulation
- `6_check_balances.ts` - Comprehensive balance checker
- `util.ts` - Utility functions for keypair management and formatting

## 🚀 Quick Start

### Prerequisites

1. **Node.js and npm** installed
2. **Solana CLI** installed and configured for devnet
3. **Anchor** framework installed
4. **TypeScript** installed globally: `npm install -g typescript`

### Installation

```bash
# Install dependencies
npm install

# Build the program (if not already built)
anchor build

# Deploy to devnet (if not already deployed)
anchor deploy --provider.cluster devnet
```

### Running the Scripts

The scripts should be run in order:

```bash
# 1. Initial setup
npx ts-node simulate/0_setup_devnet.ts

# 2. Create strategy vaults
npx ts-node simulate/1_create_strategy.ts

# 3. Make deposits
npx ts-node simulate/2_deposit.ts

# 4. Execute arbitrage (optional)
npx ts-node simulate/4_execute_arbitrage.ts

# 5. Claim profits (after arbitrage)
npx ts-node simulate/5_claim_profits.ts

# 6. Check all balances
npx ts-node simulate/6_check_balances.ts

# 7. Withdraw funds (optional)
npx ts-node simulate/3_withdraw.ts
```

## 📊 State Management

The scripts use JSON files to maintain state between runs:

- `nyx_state.json` - Program state including PDAs, vaults, and user information
- `balances.json` - Current balances for all accounts
- `balance_report.json` - Detailed balance report (generated by check_balances.ts)

### Keypairs

The scripts automatically create and manage keypairs:

- `admin-keypair.json` - Program administrator
- `deployer-keypair.json` - Transaction payer
- `amm-wallet.json` - AMM wallet for arbitrage execution
- `depositor-keypair.json` - Test user for deposits

## 🔧 Script Details

### 0_setup_devnet.ts

**Purpose**: Initialize the program on devnet and create all necessary accounts.

**What it does**:
- Creates keypairs for admin, deployer, and AMM wallet
- Requests SOL airdrops for all accounts
- Initializes administrators
- Creates global config with fees and thresholds
- Creates test USDC mint
- Funds AMM wallet with USDC
- Creates strategy vaults for risk levels 1, 2, and 3

**Output**: `nyx_state.json` and `balances.json`

### 1_create_strategy.ts

**Purpose**: Create additional strategy vaults if needed.

**What it does**:
- Loads existing state
- Creates strategy vaults for risk levels 1, 2, and 3
- Verifies vault creation
- Updates state with new vault PDAs

### 2_deposit.ts

**Purpose**: Simulate user deposits into strategy vaults.

**What it does**:
- Creates or loads a depositor keypair
- Funds depositor with SOL and USDC
- Makes deposits to all risk levels:
  - Risk Level 1: 1,000 USDC
  - Risk Level 2: 2,000 USDC
  - Risk Level 3: 1,500 USDC
- Tracks deposits in state
- Updates balances

### 3_withdraw.ts

**Purpose**: Simulate user withdrawals from strategy vaults.

**What it does**:
- Loads depositor information
- Withdraws from all risk levels:
  - Risk Level 1: 500 USDC
  - Risk Level 2: 1,000 USDC
  - Risk Level 3: 750 USDC
- Updates state and balances
- Verifies withdrawal amounts

### 4_execute_arbitrage.ts

**Purpose**: Simulate arbitrage execution by AMM wallet.

**What it does**:
- Uses AMM wallet to execute arbitrage
- Generates profits for each risk level:
  - Risk Level 1: 100 USDC profit
  - Risk Level 2: 200 USDC profit
  - Risk Level 3: 150 USDC profit
- Updates vault profit totals
- Tracks AMM wallet balances

### 5_claim_profits.ts

**Purpose**: Simulate users claiming profits from treasury.

**What it does**:
- Checks user deposits in each vault
- Claims profits for eligible users
- Calculates profit earned
- Updates user balances
- Shows profit distribution

### 6_check_balances.ts

**Purpose**: Comprehensive balance checker for all accounts.

**What it shows**:
- Program state and PDAs
- Strategy vault balances and status
- Treasury vault balance
- User balances and deposits
- AMM wallet balances
- Detailed balance report in JSON

## 🛠️ Troubleshooting

### Common Issues

1. **Insufficient SOL**: Scripts automatically request airdrops, but devnet limits apply
2. **Account not found**: Ensure previous scripts completed successfully
3. **Transaction failures**: Check devnet status and retry
4. **State file corruption**: Delete state files and restart from setup

### Reset Everything

```bash
# Remove all state files
rm simulate/*.json

# Start fresh
npx ts-node simulate/0_setup_devnet.ts
```

### Manual Funding

If airdrops fail, manually fund accounts:

```bash
# Fund admin account
solana airdrop 2 <admin-pubkey> --url devnet

# Fund deployer account  
solana airdrop 2 <deployer-pubkey> --url devnet
```
